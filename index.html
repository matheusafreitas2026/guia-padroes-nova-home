Objetivo do documento

Ser o apoio para as equipes de Produto, Design e Desenvolvimento na estruturação visual da Nova Home. O foco é garantir que a disposição dos dados respeite os hábitos visuais humanos, reduza a carga cognitiva e elimine a poluição visual, entregando valor de forma rápida, intuitiva e performática.

Princípios Gerais de Visualização de Dados para Devs

A Regra dos 5 Segundos & Aceleração Cognitiva

Um gráfico em uma home ou dashboard corporativo serve para tomar decisões ou identificar anomalias, não para ser decorativo. O usuário deve entender a mensagem principal (a "história" dos dados) em no máximo 5 segundos.

4.0s Tendência

Proporção Dados-Tinta

Conceito formulado por Edward Tufte: Maximize a tinta de dados, elimine a tinta que não é dado.

✕ Ruído / 3D / Grade
✓ Tinta de Dados Pura
O que eliminar (Tinta Não-Dado):
  • Linhas de grade (gridlines) muito escuras ou espessas. Use no máximo a cor do token de borda suavizada.
  • Bordas ao redor do container do gráfico se a hierarquia já for mantida por espaços em branco.
  • Efeitos 3D, sombras projetadas excessivas e gradientes chamativos no corpo das formas.
  • Legendas duplicadas quando os dados já possuem labels diretos nas barras ou fatias.

Redução de Carga Cognitiva com Leis da Gestalt

A mente humana busca padrões visuais automaticamente. Devemos estruturar a UI para guiar essa percepção:

  • Proximidade: Agrupar labels e métricas perto de suas respectivas barras/linhas.
  • Similaridade: Usar a mesma cor para o mesmo tipo de dado entre gráficos diferentes.
  • Fechamento: Permitir que o olho 'complete' o gráfico sem poluir com eixos pesados.
  • Enclausuramento: Usar cards suaves para delimitar contextos de indicadores distintos.
  • Conexão: Usar linhas limpas e finas para vincular pontos temporais contínuo

Catálogo de Gráficos PO UI: Quando Usar, Evitar e Acessibilidade

Gráfico de Área

Combina a linha temporária com o preenchimento inferior. A versão disponível no PO UI é o Overlapping Area Chart(Área sobreposta).

Quando Usar:
  • Representar totais acumulados ao longo do tempo (ex: volume financeiro acumulado).
  • Exibir tendências onde a diferença de volume/área abaixo da linha agrega valor à interpretação.
O que EVITAR:
  • Não sobreponha mais de 3 séries de dados. Mais do que isso cria oclusão visual e poluição.
  • Não use opacidade de preenchimento em 100%. A transparência da área preenchida deve ser ajustada entre 15% e 30% para não esconder séries que estejam atrás.
✓ CERTO / RECOMENDADO Visualização Recomendada: Série A, Série B, Série C
  • Usar no máximo 3 séries de dados simultâneas.
  • Manter a transparência da área entre 15% e 30% para não ocluir os dados ao fundo.
✕ ERRADO / A EVITAR Visualização Obscurecida (5 séries sobrepostas)
  • Evitar sobrepor mais de 3 séries de dados simultâneas.
  • Não utilizar preenchimento 100% opaco que impeça a leitura.

Gráfico de Barra

Organizado com categorias no eixo vertical (Y) e valores numéricos no eixo horizontal (X).

Quando Usar:
  • Comparar itens categorizados diretamente entre si (ex: Vendas por Filial, Chamados por Departamento).
  • Sempre que os nomes das categorias/rótulos forem longos. O eixo vertical evita que o texto seja truncado com reticências ou precise ser inclinado.
Boas Práticas:
  • Prefira o gráfico de barras quando houver mais de 7 a 10 categorias para análise.
  • Ordene as barras por valor (do maior para o menor) para facilitar a comparação rápida, a menos que haja uma ordem natural (como faixas etárias ou processo de etapa).
Acessibilidade (WCAG 2.2):
  • As barras devem apresentar rótulos visíveis de dados (data labels) diretamente ao lado da extremidade da barra para evitar o movimento sacádico contínuo dos olhos até o eixo X.
  • Área de Toque/Hover: Garanta que a área interativa do tooltip cubra a barra inteira com espaçamento suficiente entre barras de no mínimo 8px para evitar acionamentos incorretos em telas sensíveis ao toque (WCAG 2.5.8 Target Size - Minimum).

Quando Usar:

  • Comparações entre um número reduzido de categorias (idealmente até 7).

Gráfico de Gauge Semicircular

Exibe o progresso de um valor individual dentro de uma escala predefinida (ex: 0% a 100%).

Quando Usar:

Visualização rápida de performance individual contra uma meta fixa (ex: % da meta de vendas atingida no mês, uso de cota do servidor).

O que EVITAR:

Não utilize o gauge para séries históricas ou para comparar múltiplos elementos ao mesmo tempo. Use apenas um valor corrente por widget de Gauge.

Acessibilidade (WCAG 2.2):

Não confie apenas na cor do arco (ex: vermelho para ruim, verde para bom) para transmitir se a meta foi alcançada. Exiba o valor numérico exato em texto centralizado dentro do semicírculo com tamanho relativo amplo e peso bold, juntamente com o texto descritivo do status (ex: "75% - Dentro do Esperado") (WCAG 1.4.1 Use of Color).

Gráfico de Linha

Conecta pontos de dados contínuos em uma escala comum.

Quando Usar:
  • Análise de séries temporais contínuas (tendências ao longo de dias, semanas, meses, anos).
  • Comparações de tendências entre múltiplos grupos (máximo de 4 linhas simultâneas).
O que EVITAR:
  • Não utilize gráfico de linha para categorias discretas que não tenham ordem sequencial lógica (ex: Filial A, Filial B, Filial C). Para isso, utilize Coluna ou Barra.
Acessibilidade (WCAG 2.2):
  • Indicadores de Forma (Markers): Todas as linhas devem possuir marcadores em cada ponto de dados (círculos, quadrados, triângulos) e/ou padrões de traço (linha contínua, tracejada), além da cor. Isso é imprescindível para usuários daltônicos identificarem a qual série a linha pertence (WCAG 1.4.1 Use of Color).
  • Espessura mínima recomendada para a linha: 2px a 3px.
✓ CERTO / RECOMENDADO Tendência Mensal de Vendas (Círculos, Quadrados, Losangos)
  • Usar para séries temporais contínuas (máximo de 4 linhas simultâneas).
  • Utilizar marcadores de forma (círculos, quadrados) ou padrões de traço para diferenciar séries (WCAG 1.4.1).
  • Manter espessura da linha entre 2px e 3px.
✕ ERRADO / A EVITAR Vendas por Filial (Séries discretas sem ordem sequencial)
  • Não utilizar gráfico de linha para categorias discretas sem ordem sequencial (utilize Coluna ou Barra).
  • Evitar linhas diferenciadas apenas por cor sem marcadores visuais de forma.

Gráfico de Pizza e Gráfico Rosca

Exibem a proporção das partes em relação ao todo (soma de 100%).

Quando Usar:
  • Exclusivamente para ilustrar partes estáticas de um todo com poucas categorias.
  • O gráfico de Rosca é preferível ao de Pizza, pois o espaço central vazio permite a inclusão do valor total numérico acumulado.
O que EVITAR:
  • NUNCA utilize para comparar dados. O cérebro humano é péssimo para comparar áreas angulares e volumes.
  • NUNCA ultrapasse 5 fatias. Gráficos de pizza com muitas fatias tornam-se ilegíveis e geram legendas poluídas.
  • Fatias menores do que 10% do total inviabilizam a percepção visual direta.
Regra Técnica de Negócio (PO UI):

Se um item for menor que 10% e existirem múltiplos itens pequenos, agrupe-os obrigatoriamente em uma única fatia chamada "Outros". O detalhamento desses itens deve ser disponibilizado através de uma tabela de apoio ou drill-down.

Acessibilidade (WCAG 2.2):
  • Não coloque rótulos soltos fora do gráfico ligados por linhas finas ("linhas de chamada"). Mantenha a legenda clara com rótulo + porcentagem numérico visível (ex: "Aprovações ERP: 45%").
  • A separação entre as fatias deve conter um traço (stroke) de divisão branco de no mínimo 2px para diferenciar fatias adjacentes com tons similares (WCAG 1.4.11 Non-text Contrast).

Gráfico de Radar

Exibe dados de múltiplas variáveis quantitativas mapeadas em eixos a partir de um ponto central.

Quando Usar:

Avaliar e apresentar um perfil multi-atributo (ex: Avaliação de competências, análise de conformidade de processos corporativos em 5 eixos distintos).

O que EVITAR:

Não utilize para mais de 2 entidades sobrepostas ao mesmo tempo, pois a área sombreada resulta em sobreposição opaca de difícil leitura.

Acessibilidade (WCAG 2.2):

Devido à alta complexidade matemática do layout visual de teia de aranha, garanta que os leitores de tela tenham acesso direto a uma tabela HTML estática equivalente (<table>) com os atributos e notas mapeados via atributo aria-describedby (WCAG 1.1.1 Non-text Content).

Matriz de Decisão Rápida para DEVs (Qual Gráfico Escolher?)

Para evitar a implementação de tipos de gráficos incorretos nos módulos da Nova Home, utilize este fluxo de decisão simplificado:

Diretrizes de Hierarquia da Informação

2.1 Princípios Fundamentais de Hierarquia

Cada elemento na Home deve ter um propósito claro para a tomada de decisão da persona (o principal usuário desta tela do sistema, seja ela estratégica ou operacional). Tudo o que for considerado "ruído" deve ser eliminado seguindo os princípios fundamentais a seguir.

2.1.1

Regra da Tela Única

A Home deve exibir as informações críticas necessárias em uma única tela. Evite a necessidade de rolagem excessiva (scroll), por gerar sobrecarga cognitiva no usuário. A recomendação é que todos os dados essenciais estejam visíveis ao carregar, sem necessidade de rolagem, algo que também elimina o excesso de conteúdo.

1ª Camada • Visão Executiva

1º camada ou linha correspondente à visão executiva, deve determinar o “O quê” está sendo demonstrado. Para inserir suas informações considere que olho humano busca padrões numéricos grandes primeiro, portanto a prioridade devem ser big numbers. No caso da ausência destes números, utilize contadores ou barras horizontais simples.

2ª Camada • Visão Operacional

2º camada ou linha correspondente à visão operacional, deve determinar o “Por quê?” está sendo demonstrado. Priorize inserir uma camada de visualização de dados, como gráficos, por exemplo, que explicam as variações e o comportamento dos KPIs apresentados na 1ª camada. É possível que essa camada seja composta por uma única linha de dados única, mas que não deve ultrapassar duas linhas, a fim de respeitar a área útil de rolagem.

3ª Camada • Visão Detalhada

3º camada ou linha correspondente a visão detalhada, deve determinar o “Onde?”. Utilize-a como uma última camada de visualização principal da tela para inserir atalhos, rotinas, gráficos complementares e informações úteis e acionáveis.

2.3

Diretrizes para considerar a carga cognitiva

Para garantir que a Nova Home funcione como um facilitador invisível num contexto onde a leitura do cenário ocorre em frações de segundo, é fundamental respeitar os limites da atenção humana e aplicar atalhos mentais de assimilação visual. As seções a seguir detalham as restrições cognitivas estabelecidas para o layout, as regras espaciais de agrupamento (Leis de Gestalt), os padrões de clareza na comunicação e os requisitos técnicos de performance necessários para sustentar essa experiência.

2.3.1 Lei da proximidade

A hierarquia visual só tem valor se as informações dispostas na estrutura da interface forem facilmente compreendidas pelo usuário, desse modo métricas e dados que se relacionam devem estar agrupadas. Essa diretriz segue uma das Leis da Gestalt, que versa sobre o agrupamento de elementos e informações.

Portanto, se no topo da nova home o time optar por exibir um KPI de "Inadimplência", por exemplo, e houver um gráfico explicativo de "Inadimplência por Mês", este deve estar posicionado imediatamente abaixo ou ao lado dele.

2.3.2 Atenção a comunicação e nomenclatura
  • Títulos e Descrições: Todos os Big Numbers e gráficos devem possuir títulos objetivos e descrições extremamente claras que representem o que aquela informação representa.
  • Atenção ao jargão técnico: Expressões técnicas que venham de banco de dados ou jargões de desenvolvimento devem ser substituídos por uma linguagem de negócios voltada ao dia a dia do cliente.
  • Padronização do nome das jornadas e rotinas cadastradas: As equipes de Produto devem definir bons nomes, além de incluir e padronizar descrições, de ambos os cadastros. Todos esses campos devem ser claros e adequados para representar a ação por trás de cada rotina ou jornada apresentada, a fim de garantir que o cliente seja capaz de diferenciar cada uma delas e também compreender de qual produto ela se refere. A nomenclatura não deve gerar ambiguidade e precisa ser consistente em todas as jornadas do Segmento. Exemplos práticos:
    • Não é adequado inserir o mesmo nome de uma rotina para a sua descrição;
    • No caso de uma rotina de contrato, por exemplo, deve-se descrever a qual tipo de contrato e de qual produto se refere, pois podem possuir diversas rotinas com ações semelhantes.
2.3.3 Quantidade máxima de itens

A Lei da Psicologia de Miller, amplamente utilizada para comunicações textuais e visuais, determina que a memória de trabalho humana processa de forma eficiente apenas de 5 a 7 itens por vez. Desse modo, exceder esse valor em uma tela causa fadiga cognitiva e impede que o usuário priorize as informações. No caso de big numbers, por exemplo, é importante evitar ultrapassar essa quantidade na mesma interface.

2.4

Hierarquia e performance de carregamento

A experiência do usuário na Nova Home depende tanto da visualização quanto da velocidade de resposta da tela e a hierarquia da informação não deve ser penalizada por lentidão sistêmica.

Portanto, o padrão de desenvolvimento construído deve considerar a arquitetura dos dados desde o início. Os times técnicos devem garantir que a extração dos indicadores para a Home seja otimizada.

2.5 & 2.5.1

Modelos de Grid e estruturas de layout

A aplicação prática das regras de hierarquia e psicologia cognitiva se materializa também através da estrutura do grid da página. O posicionamento dos cards, a variação de tamanho entre os blocos e o agrupamento espacial são os responsáveis por ditar o fluxo de leitura ocular do usuário, guiando-o do indicador mais crítico até a ação operacional.

2.5.1 Siga o exemplo: Agrupamento e Assimetria

Estruturas completamente simétricas e com cards do mesmo tamanho quebram a arquitetura F/Z. Como a própria regra dita: "se tudo tem destaque visual, nada se destaca". O olho não sabe por onde começar a ler.

Portanto, utilize variações compactas ou em zigue-zague que aplicam as Leis de Gestalt ao aproximar fisicamente um indicador do seu gráfico correspondente, criando blocos temáticos autossuficientes.

Guia Padrões de Cores

3.1. Introdução

Esta é uma proposta de direcionamento para o Guia de Estilos e Boas Práticas de Produto, com o intuito de orientar o time no desenvolvimento das telas na Nova Home RM, integrando o PO-UI e Smart-X com o Manual de Identidade Visual da TOTVS, as diretrizes de Business Intelligence (BI) e os padrões internacionais de acessibilidade da WCAG.

3.2

Diretrizes de uso para Tags de Cores (po-tag do PO-UI)

As tags são elementos visuais essenciais na Nova Home para destacar os status, categorias e métricas nos cards de KPI’s e demais listas de tarefas.

3.2.1. Tipos de Padrões Semânticos (p-type)

Esses padrões definem o tipo ou estado do sistema na tag exibida, garantindo um reconhecimento imediato dos usuários:

Success (verde)

utilizada em casos de confirmações, conclusão de tarefas ou demais resultados positivos, de sucesso ou êxito em alguma tarefa ou job.

Warning (amarelo)

utilizado em casos de alertas, avisos, pendências ou dados que exigem a atenção do usuário.

Danger (vermelho)

destacam os erros, falhas ou avisos críticos de alto risco do sistema.

Indicação de info (azul)

são informações gerais e conteúdos explicativos da interface.

Neutral (cinza)

usado geralmente quando a tag não possui nenhuma informação crítica.

3.2.2. Paleta de Categorização (Caption Tag Colors vs p-color):

Para categorização de dados e tags identificadoras, utilize as 35 cores disponíveis na paleta Caption Tag Colors (caption-tag-01 a caption-tag-35). Confira na imagem ao lado.

Contraste de Texto em Tags: nas cores da paleta Caption Tag Colors, a cor do texto é fixa e definida via token ou classe CSS. Para cores legadas (color-01 a color-12, vide imagem ao lado), o componente ajusta a cor do texto automaticamente para preservar a legibilidade de acordo com a acessibilidade, mas é indispensável selecionar tonalidades de fundo com alto nível de contraste em relação ao layout.

3.2.3. Acessibilidade Multimodal em Tags:

Em conformidade com a WCAG, as cores não devem ser o único meio de transmitir uma informação. Pode-se utilizar também a propriedade “p-icon” para adicionar ícones explicativos ou combinar com rótulos de texto claros (“p-value” ou “p-label”), garantindo autonomia para usuários com daltonismo ou com baixa visão.

3.2.4. Atenção importante:

Recomenda-se evitar a customização ou padronização de cores que não estejam contempladas na paleta Caption Tag Colors.

3.3

Boas Práticas de Cores e Contraste em Gráficos

Os gráficos presentes na Nova Home (como gráficos de pizza, colunas empilhadas e área) exigem um certo cuidado cromático para evitar sobrecarga cognitiva e assegurar o entendimento das informações para os usuários.

3.3.1. Harmonia e limitações de paleta de cores:
  • Limite a visualização a somente 2 ou 3 cores principais, utilizando variações de opacidade, sombras ou espectros de cores análogas para expressar intensidade ou subcategorias.
  • Evite a utilização simultânea de múltiplas cores saturadas (efeito "arco-íris"), que polui a interface e dificulta a hierarquia de leitura.
  • Mantenha a mesma cor para representar a mesma variável em toda a página.
3.3.2. Combinações funcionais mais recomendadas:
  • Cinza e Azul: Indicado para comparação temporal entre dados passados e atuais.
  • Azul e Laranja: Excelente opção para contraste entre dados positivos (azul) e negativos (laranja), sendo uma alternativa segura ao verde/vermelho para daltônicos.
  • Destaque por Contraste: Utilize cores vibrantes e de alto contraste exclusivamente para os dados mais relevantes, mantendo dados secundários em tons neutros ou de menor contraste (Data-ink Ratio).
3.3.3. Práticas para evitar em gráficos:
  • Nunca atribua vermelho para números positivos nem verde para números negativos.
  • Evite combinações de baixo contraste como azul claro sobre cinza.
3.4

Acessibilidade Digital e Requisitos WCAG

O desenvolvimento dos componentes e visualizações da Nova Home deve atender aos padrões internacionais de acessibilidade web (WCAG 2.2 Nível AA).

3.4.1. Contraste de Cores:

Cada texto e elemento gráfico na interface precisa atingir os índices de contraste mínimos exigidos pela WCAG com um nível de AA, em relação ao seu plano de fundo.

Consulte sempre a tabela de combinações de cores que são permitidas pelo Manual de Identidade Visual da TOTVS, ao definir as cores para cada elemento em uma interface.

3.4.2. Leiturabilidade e Redução de Ruído:

Em áreas compostas por gráficos, fotografias ou grafismos tridimensionais, garanta que legendas e rótulos estejam posicionados sobre superfícies neutras e sem ruídos visuais.

3.5

Diagnóstico e Ajustes Específicos para a Nova Home

3.5.1. Gráficos de indicadores (evolução de pedidos, fluxo de caixa, vendas por tipo etc):

Diagnóstico: as visualizações atuais utilizam um conjunto heterogêneo e altamente saturado de cores (vermelho, verde, azul, amarelo, roxo, rosa).

Recomendação: uniformizar os gráficos aplicando a paleta primária/secundária TOTVS (tons de Azul Escuro, Azul e Roxo).

Gráfico de Pizza: caso existam fatias menores que 10%, agrupe-as em uma fatia "outros" para melhorar a precisão visual.

3.5.2. Cards de Aplicativos e Tabela de Tarefas:

Diagnóstico: presença de múltiplos sinalizadores e dados de status em cards e tabelas.

Recomendação: padronizar os sinalizadores de status utilizando o componente “po-tag” com os tipos semânticos (“success” para concluído, “warning” para pendente, “danger” para cancelado ou em atraso) e ícones correspondentes (p-icon).

3.6

O Poder das Cores no Dashboard da Nova Home

3.6.1. Breve Contexto

A utilização das cores vai muito além da estética, numa interface. Trata-se de uma ferramenta funcional que orienta a atenção dos usuários, indicando interatividade e organização da hierarquia de informações. Segundo as diretrizes do Animalia Design System da TOTVS, bem como das normas de acessibilidade (WCAG), o uso das cores deve ser intencional e bem dosado, garantindo que a informação seja compreensível para todos os utilizadores, levando em consideração também as suas capacidades visuais.

Este guia se destaca na aplicação prática de proporções (como a regra 60-30-10), além de critérios rigorosos de contraste e acessibilidade; bem como da seleção correta de diversos tipos de gráficos a serem utilizados.

O nosso maior objetivo é evitar a sobrecarga visual e garantir que os elementos críticos, como alertas de erro ou estados de sucesso, sejam imediatamente identificados através de uma correta combinação de cores e outros componentes visuais da interface.

3.6.3. Recomendação de boas práticas
  • Siga a regra 60-30-10: distribua as cores mantendo uma proporção de 60% para a cor predominante, 30% para cores de apoio e 10% para cores de destaque, para garantir um equilíbrio no padrão estético e visual.
  • Garantia de um contraste mínimo: o nível recomendado de contraste deve ser de pelo menos 4.5:1 para textos e 3:1 para os demais componentes gráficos, utilizando algumas ferramentas tais como o "Coolors.co".
  • Use cores semânticas corretamente: procure sempre utilizar tons de verde para identificar os dados positivos ou de sucesso, e os tons de vermelho para os dados negativos ou de erro, mantendo uma consistência cultural e intuitiva em relação à memória cognitiva dos usuários.
  • Redundância visual: combine as cores com ícones, textos ou diferentes pesos de fonte para que a informação não dependa exclusivamente da percepção cromática.
3.6.4. O que evitar (alguns erros mais comuns)
  • Evite utilizar um nível de 100% de preto (#000): o contraste extremo de preto pode ser incômodo na leitura, em alguns casos. Prefira utilizar tons de cinza escuro, veja o exemplo nos quadros da imagem ao lado.
  • Evite utilizar cores com alta saturação nos componentes: as cores muito saturadas são agressivas aos olhos, dessa forma, dê preferência às cores menos saturadas (tons pastéis) para manter o foco somente no conteúdo.
  • Não utilize somente as cores para diferenciação: não confie apenas nas cores para transmitir uma mensagem crítica, pois os usuários daltônicos ou em ambientes com reflexo podem perder uma informação importante.
3.6.5. Cores em gráficos
  • Consistência de dados: use uma única cor para representar o mesmo tipo de dados (ex: vendas mensais). Utilize cores diferentes apenas para comparar as categorias que forem distintas.
  • Limite a quantidade de fatias dos gráficos: nos gráficos de pizza ou de rosca, evite utilizar mais de cinco fatias para não comprometer a legibilidade e o entendimento rápido dos usuários.
  • Agrupamento "outros": em gráficos de rosca, valores menores de 10% devem ser agrupados em uma seção separada, tipo "outros" para evitar poluição visual, em relação aos demais valores maiores.
  • Hierarquia de visualização, na "regra dos 5 segundos": posicione as informações críticas no topo superior esquerdo da interface, para um melhor entendimento imediato, por parte dos usuários.
  • Elimine o excesso de casas decimais: procure sempre arredondar os valores para uma maior clareza visual (ex: use "850k" em vez de "$850.010,25").
